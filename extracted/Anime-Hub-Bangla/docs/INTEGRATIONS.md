# External integrations

## Video
Select Cloudflare Stream or Bunny Stream after creating a provider account. Add credentials only to the API host. Implement provider upload, encoding webhook, signed playback URL, thumbnail and deletion flows before enabling episode publishing. A manual URL field should accept only sources you are authorized to use.

## R2 storage
Create a private R2 bucket and scoped API token. Upload via short-lived presigned URLs generated by the backend. Keep the bucket private unless public assets are intended.

## Adsterra
Adsterra reporting requires the account's supported API/report access. Import actual provider metrics; if access is unavailable, show "Not connected" or allow CSV import. Never fabricate impressions, clicks, CPM or earnings. Do not click your own ads or encourage invalid traffic.

## Payments
SSLCOMMERZ and mobile financial services require merchant onboarding and provider-approved credentials. Implement server-side payment initiation, signed callback verification, duplicate-payment protection, refunds and reconciliation. Do not collect card/mobile-wallet credentials directly.

## Premium manager
Track plans, entitlements, provider subscription IDs, billing dates, usage and transaction status. Only Super Admin should manage paid integrations and billing by default.


## Cloudflare Stream upload and playback

The admin Episode Manager supports direct browser-to-Cloudflare uploads. Configure these variables in `apps/api/.env` (never in the web app):

- `CLOUDFLARE_STREAM_ACCOUNT_ID`
- `CLOUDFLARE_STREAM_API_TOKEN` — create a scoped API token with Stream edit permissions for the intended account.

Restart the API after adding them. In Admin → Episodes, choose an anime, select a video file in **Upload video to Cloudflare Stream**, wait for the upload to finish, then save the episode. The API creates a one-time Direct Creator Upload URL; the browser sends the file directly to Cloudflare, and the returned Stream UID is stored as the episode video ID. Published episodes use Cloudflare's `iframe.videodelivery.net` player.

This starter currently creates publicly playable Cloudflare Stream videos (`requireSignedURLs: false`). Do not publish private or restricted media through this setting. Signed playback, upload size policy, moderation, deletion/synchronization and provider webhooks should be configured before a production launch. Cloudflare Stream is a paid service; storage and delivery charges depend on usage.

For manual sources, the episode provider ID field accepts an HTTPS MP4/WebM/HLS URL or an HTTPS embed URL. Only use media you own or are licensed to distribute. Bunny Stream upload is not implemented yet; choosing Bunny in the admin form alone does not upload or play a video.

## Premium payment review (current implementation)

The current premium flow is **manual transaction-reference submission**, not a live gateway checkout. A user selects bKash, Nagad, Rocket or SSLCOMMERZ, enters the exact amount and transaction reference, then submits a monthly/yearly request. The API stores it as `PENDING`; no Premium access is granted at submission time.

An authorized Super Admin/Admin opens `/admin`, checks the transaction in the provider's own merchant dashboard, and then approves or rejects it. Approval activates the associated membership for one month or one year from approval time. Rejection marks it failed. Every review is written to `audit_logs`.

Before enabling this in production:
- Publish the official merchant payment instructions and plan prices in the site.
- Verify each transaction directly with the provider; never trust a screenshot or a client-side success message alone.
- Apply database migrations (`database/schema.sql`) to the same database used by the API.
- Keep merchant credentials and gateway secrets only in server-side environment variables.
- Do not ask users for PINs, passwords, or OTPs.

Live checkout, signed webhook verification, refunds and reconciliation are **not implemented yet**. SSLCOMMERZ and mobile-wallet API integrations require approved merchant accounts and provider-issued credentials.

## Adsterra and direct sponsors
The admin dashboard supports importing daily Adsterra report figures (date, impressions, clicks, revenue) into `ad_metrics_daily`. The import is a manual data-entry path and does not imply an active Adsterra API connection. Keep the currency as USD unless the source report explicitly uses BDT. Duplicate provider/date/placement imports update the existing row.

Direct sponsor leads are stored in `sponsors` with company, deal value and pipeline status. The displayed active/completed sponsor value is a contracted-value indicator, not proof that money has been received. Record actual collected funds separately in `revenue_entries` with status `CONFIRMED` after reconciliation.

## Playback analytics
Authenticated clients can submit `POST /api/user/playback-event`. The API checks that the episode exists and is published, then records the signed-in user, anime, episode, event type and watched seconds. Analytics counts are therefore event counts, not unique video views or audited watch-time measurements. Do not use them for advertising invoices without a separate validated measurement process.
